# 真实保险后端能力优化说明

本文档用于记录当前项目和真实保险公司后端系统相比，已经补齐的能力以及后续建议继续建设的能力。

## 本次已优化

### 1. 接口鉴权

已增加无登录随机 token 鉴权：

- `POST /api/insurance/auth/token/` 每次生成一个随机 `access_token`。
- token 写入 Redis/Django cache，有效期由 `INSURANCE_TOKEN_TTL` 控制，默认 7200 秒。
- 业务接口必须传 `Authorization: Bearer <access_token>` 或 `X-Insurance-Token`。
- `INSURANCE_API_KEY` 保留为内部系统固定密钥绕过 token 校验。
- 鉴权失败仍返回统一响应结构：`code=999`。

### 2. 产品和费率配置表

已增加以下配置表：

| 表对应模型 | 作用 |
| --- | --- |
| `Product` | 产品主数据：产品代码、名称、详情、上下架状态、年龄范围、保障期限 |
| `ProductPlan` | 产品计划：基础版、标准版、尊享版、基础保费 |
| `ProductCoverage` | 保障责任：责任代码、责任名称、保额 |
| `AgeRateFactor` | 年龄费率因子 |
| `OccupationRateFactor` | 职业类别费率因子 |

试算接口已改为读取数据库配置，不再使用代码里的产品字典。迁移会初始化示例产品 `PA_C_ACCIDENT`。

### 3. 产品查询接口

已增加：

```http
GET /api/insurance/products/
GET /api/insurance/products/{product_code}/
```

前端或接口用例可以先查询产品、计划、保障责任和费率配置，再调用保费试算。

### 4. View 注释

`apps/insurance/views.py` 已给每个 View 类增加中文 docstring，标明：

- 对应接口路径
- 接口用途
- 核心业务含义

## 后续建议继续补齐

### 1. 更完整的权限模型

当前 API Key 适合内部联调和简单系统间调用。真实生产还需要：

- 用户登录态、JWT 或 OAuth2。
- C 端用户、运营人员、核保人员、支付回调方分角色授权。
- 接口级权限控制，例如人工核保接口不能给普通 C 端调用。
- API Key 分渠道管理、过期时间、禁用状态和调用审计。

### 2. 产品中心能力

当前产品配置已落表，但还缺：

- 产品版本号和费率版本号。
- 产品上下架审批流。
- 产品条款、免责说明、投保须知、健康告知模板。
- 地区、渠道、职业、年龄维度的可售规则。
- 产品配置变更后的历史保单追溯能力。

### 3. 费率中心能力

当前只支持年龄和职业类别两个费率因子。真实系统通常还需要：

- 地区费率、渠道费率、短期费率、折扣规则。
- 多责任分项保费。
- 费率版本生效期。
- 试算结果锁价和价格快照校验。

### 4. 核保规则中心

当前核保规则写在代码里。后续可以配置化：

- 健康告知问卷和答案评分。
- 职业、年龄、保额、历史理赔等规则组合。
- 自动核保规则版本。
- 人工核保任务池、分配、复核、回退。

### 5. 支付和出单生产化

当前支付是模拟接口。真实系统还需要：

- 支付网关验签。
- 支付回调幂等号和重放保护。
- 支付订单关闭、退款、撤单。
- 保单号生成规则中心。
- 电子保单 PDF 生成、签章、下载鉴权。

### 6. 数据安全和审计

保险系统会处理大量敏感信息，后续需要：

- 身份证、手机号、邮箱脱敏展示。
- 字段级加密存储。
- 操作审计表。
- 请求签名、防重放、防刷。
- 日志脱敏和隐私合规。

### 7. 稳定性和工程化

后续建议补：

- 幂等键 `Idempotency-Key`。
- 业务事件表或 outbox，保证支付、出单、通知最终一致。
- 统一业务错误码枚举。
- OpenAPI/Swagger 文档。
- 更完整的接口测试数据工厂和端到端流程用例。
